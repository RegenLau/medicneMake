# 视频制作改造实施记录

实施依据为《视频制作方案.md》。基线为 `da84bdf`。各阶段验收通过后单独提交。

## 阶段 A　抽出布局和内容渲染器

### 计划

- 新增 `public/stage.html`、`public/stage/layout-engine.js`、`public/stage/contents.js`、`public/stage/player.js` 和内容绘制所需的模块与样式。把信息图组件和现有四种内容的绘制移到共享模块。`template-renderer.js`、`code-motion.html`、`code-motion.js` 和 `svg-motion.js` 保留原入口，供现有编辑器和旧任务使用。
- 在 `public/assets/library/layouts/info-classic.json` 保存现有信息图的区域配置。更新 `catalog.json`、`asset_library.py` 和 `server.py`，登记内置布局、校验布局定义，并让 `config.stageRender` 保持关闭。更新 `public/index.html` 和 `render_svg_video.mjs` 的共享模块加载顺序。
- 新增 `tests/test_stage_layout.py` 和 `tests/compare-stage-frames.mjs`。用 Chromium 比较 `da84bdf` 与新模块的 1280×720 截图。分别验证 `image`、`card`、`scene`、`svg` 的 0%、25%、50%、75%、100% 位置，并额外覆盖开场提问与结尾定格。校验未知组件和样式、越界、媒体区尺寸、字幕重叠、禁止字段及字符串。运行全量 Python 测试和 JavaScript 语法检查。

### 实际改动

- 公共布局组件和位置计算进入 `layout-engine.js`。现有 SVG 和代码动效入口改用共享内容模块。布局清单加入信息图模板，保留开场提问和结尾定格两套区域。
- 新增独立舞台及严格布局校验。阶段 A 保持旧合成入口，`config.stageRender` 为 `false`。

### 验收结果

- `node tests/compare-stage-frames.mjs <输出目录>` 对比基线 `da84bdf`。每种内容和特殊版式各比较 5 帧，共 30 帧。阈值是各 RGB 通道的平均绝对差 ≤ 0.12（取值 0–255），任一通道差大于 8 的像素占比 ≤ 0.01%。

| --- | ---: | ---: | ---: |
| AI 完整图 | 5 | 0.016218 | 0.0000% |
| 信息图动效 | 5 | 0.016218 | 0.0000% |
| 代码动效场景 | 5 | 0.016218 | 0.0000% |
| SVG 演示动画 | 5 | 0.016752 | 0.0000% |

- 首次对比使用默认 Chromium 图形配置，结尾第 0 帧在头像区域出现 147 个差值大于 8 的像素，占 0.01595%。将两组截图统一为 Chromium 软件光栅化后通过，阈值保持原值。对比脚本固定此配置。
- 布局白名单验证通过 4 项测试，覆盖未知组件和样式、越界、内容区过小、字幕重叠，以及 HTML、CSS 和 JS 字段。全量 Python 测试通过 60 项（本机使用 `python3`）。指定 JavaScript 文件及截图对比脚本语法检查通过。
- 旧 SVG 导出入口附加验证输出 2.000 秒、1280×720 的 H.264/AAC MP4，使用无配音的本地测试分镜。

### 未达成与偏差

- 阶段 A 最终验收全部通过。旧 SVG 保留标题位置和既有动效，以满足本阶段画面一致性。新舞台的转场和时间线在后续阶段接入。

## 阶段 B　统一时间线与合成管线

### 计划

- 新增 `stage_video.py`，集中计算配音时长、字幕节拍、分镜边界、素材清单和舞台导出参数。`server.py` 仅对带 `stage: true` 的请求启用新管线，并保留所有旧合成入口和旧任务数据。
- 新增 `scripts/render-stage.mjs`，复用 `public/stage.html`，用 Playwright 运行逐帧绘制和截图，保存 `events.json` 与逐帧输入清单。更新舞台播放器，增加静止画面复用、对口型头像帧及统一转场的接口。
- 新增时间线单元测试和可重复的 `tests/compare-stage-exports.py`。对旧作品及转换后作品分别启动新进程，导出实际 MP4，检查 ffprobe 时长差小于一帧、VTT 字节一致和画面抽帧差异。独立测量 60 秒 AI 完整图、60 秒代码动效合成耗时。
- 一致性和耗时通过后，才将 `config.stageRender` 改为默认开启。合成验证使用已有图片或本地测试图、无配音或本地缓存；不调用计费视频服务。

### 实际改动

- `stage_video.py` 校验分镜和素材，`server.py` 的 `build_timeline` 复用配音缓存、旧时长及字幕计算函数。只有 `stage: true` 的合成请求进入新管线。旧请求、旧任务重试和三条旧导出仍用原入口。
- `render-stage.mjs` 用现有 Playwright 截图，输出帧清单、`events.json` 和实际截图数量。先复用静态时间段，再复用绘制内容完全相同的连续帧。服务器保留手动出场音效，输出使用的布局和素材版本。
- 旧图片作品转换后保留原来的整帧淡入。新作品的换幕只淡入内容区。支持逐帧头像输入，本阶段计时样本使用无形象。

### 验收结果

- `python3 -B tests/compare-stage-exports.py <输出目录>` 每次从新 Python 进程开始计时，旧完整图链路包含浏览器帧准备。原规格上限完整图 2×、代码动效 1×。两种各抽取 6、30、54 秒的画面，RGB 通道平均绝对差阈值 1.0、绝对差大于 8 的通道占比阈值 1.2%。字幕 VTT 逐字节比较。

| 60 秒作品 | 旧、新实际成片 | 差值与上限 | 旧、新合成耗时 | 耗时比与上限 | 字幕 | 最大抽帧均差／大于 8 占比 |
| --- | --- | --- | --- | --- | --- | --- |
| AI 完整图 | 60.023220 s / 60.000000 s | 0.023220 s < 1/24 s | 5.543 s / 6.614 s | 1.193 < 2 | 字节一致 | 0.677985 / 0.4356% |
| 代码动效 | 60.000000 s / 60.000000 s | 0 s < 1/25 s | 27.552 s / 8.510 s | 0.309 < 1 | 字节一致 | 0 / 0% |

- 实际截图数为完整图 29/1440 帧、代码动效 290/1500 帧。完整图余下的时长差来自旧文件的封装尾部，低于一帧。
- 初测代码动效耗时比分别为 1.006462 和 1.000012，均未达标。复用绘制结果相同的截图后重新跑完整测试，达到 0.309。耗时、时长及抽帧阈值保持原值。通过后将 `config.stageRender` 设为默认开启，可通过 `STUDIO_STAGE_RENDER=0` 关闭入口。
- 全量 Python 测试通过 63 项。缓存配音测试使用本地 4.000 秒 WAV，得到 5.150 秒分镜、124 帧和 4.150 秒第二节拍起点。JavaScript 语法检查通过。

### 未达成与偏差

- 阶段 B 最终验收全部通过。两组基准均为无配音、无形象的本地作品。头像逐帧切换接入管线，数字人服务未调用。事件文件的结构已接通，事件规则和音效在阶段 E 接入。

## 阶段 D　Mix 模式和统一脚本生成

### 计划

- 新增 `mix_plan.py` 集中处理统一脚本、能力清单、候选素材、编排校验、预算和兜底。更新 `catalog.json`、`draft_content.py` 和 `server.py`，由独立 DeepSeek 调用编排已经写好的全片脚本。重跑时保留手动幕及已有媒体，费用进入文字生成账本。
- 扩展 `public/stage-studio.js` 和样式，加入 Mix/固定方式、预算、原因展示、重新编排全片和本幕重新判断。Playwright 使用模拟模型响应验收页面，截图保存到 `docs/验收截图/D/`。
- 新增模拟模型单元测试和境内本机 DeepSeek 评测脚本。仅用方案的 8 个主题做真实评测，记录到 `docs/mix-eval.md`，包含选用方式、原因、降级、预算、用量以及未过的指标。模拟或真实评测都不提交生图或视频任务。

### 实际改动与验收

- 公共脚本和编排通过两个独立的 DeepSeek 请求完成。编排能力和参数取自清单，素材候选最多 10 个。固定方式直接由脚本推导字段，固定 SVG 另调用一次选择道具。编排失败时仍可继续编辑和合成。新增了滴眼液 SVG 道具。
- 7 项 Mix 专项测试通过。验证了布局能力受限时使用备用方式、预算按 90/75/25 优先级保留前两幕、零预算时 0 张图、解析或网络失败后全片兜底、全片重排保留手动幕、固定方式和仅本幕重排。全量 72 项 Python 测试、全部 JS 语法检查和 30 帧回归通过。回归的最大 RGB 平均差异 0.016752，通道差超过 8 的像素比例为 0%。
- [真实评测](mix-eval.md)覆盖 8 个主题、40 幕。最终 40/40 条理由提到本幕的具体内容，实物操作幕 10/16 使用 SVG，8/8 片各用 2–3 种方式，8/8 片均为 0/2 张 AI 完整图，最终 1 幕走备用方式。18 次文本请求的用量估算 ¥0.16143408，包含 2 次必要重试。药师需要复核口播、理由与图形是否吻合。
