## 0. 开工前须知

- 工作区有大量未提交改动（插画底图功能，以及布局、主题、素材库相关的并行修改）。**先让用户提交或确认当前状态，不要回退、覆盖或清理任何现有改动。**
- 测试命令：
  - Python：`PYTHONPATH=. python3 -m unittest discover -s tests -p 'test_*.py'`（当前 100 个，全部通过）
  - 渲染：`node tests/stage-art.mjs <art.png> <outdir>`
  - UI 端到端：`node tests/stage-art-ui.mjs`、`tests/stage-shot-production-ui.mjs`、`tests/stage-g1.mjs`，参数都是 `origin sandbox screenshots`。
  - 端到端测试要在沙盒副本里跑：用 `rsync` 复制仓库到 `/tmp/...`，再用 `tests/stage_d_fixture.py` 的假 DeepSeek 启动 `server.py`，并设置 `STUDIO_PORT`。不要在真实 `.studio` 里跑，也不要调用付费接口。
- **旧作品必须还能打开、预览和导出。** 已保存的 `svg`、`mg`、`asset` 幕要能自动迁移，或继续按旧方式渲染。
- DeepSeek 只做选择和填充数据。所有返回值在后端按清单校验，不通过就降级到默认值。不允许模型新增医学事实，屏幕上出现的数字必须能在本幕口播或要点里找到。

### 现状速览

| 制作方式 | kind | 现在怎么做 | 关键位置 |
|---|---|---|---|
| AI 完整图 | `image` | Seedream 出整幅图 | `mix_plan.py`、`stage-studio.js` |
| 信息图动效 | `card` | 按 `points.type` 套一个固定卡片，`TemplateVideo.renderFallbackCard`；DeepSeek 只选 `motionStyle` | `public/stage/contents.js` 的 `card`、`scene-content.js` 的 `animateTemplateCard` |
| 代码动效场景 | `scene` | 8 个固定 `visual` 模板（hook/mechanism/compare/steps/timeline/checklist/warning/summary），每个只有一种排版 | `scene-content.js` 的 `buildDynamicSceneHtml`，配置在 `catalog.json` 的 `stage-config.sceneDefaults` |
| SVG 演示动画 | `svg` | 9 个预制道具动作 | `svg_motion.py`、`public/stage/svg-content.js` |
| 素材库素材 | `asset` | 用一张图或 SVG **替换整个内容区** | `contents.js` 的 `asset`、`stage_video.py` 的 `validate_shot` 最后一个分支 |

- Seedance 视频生成已经有现成实现，`server.py` 的 `source_clip` 支持首帧和尾帧；模型清单在 `VIDEO_MODELS`，计费在 `work_costs.video_cost`。

## 第 1 期：精简入口（小改动，先做）

   - `FIXED_MODES = ("image", "card", "scene")`。
   - Mix 的 `presenters` 只给 `image`、`card`、`scene`。删除 Mix 指令里关于 SVG beats 和 mgRequest 的说明。
   - `arrange_mg` 和 `mode == "svg"` 分支保留给旧接口调用，但新草稿不再走这两条路。
   - `validate_setup` 的 Mix 条件改为“布局支持 card 或 scene”。
3. 分镜编辑器“本幕制作方式”按钮改成：
   `AI 完整图`｜`信息图动效`｜`代码动效场景`｜`AI 演示视频`｜`AI MG 动画`

   - 旧作品里的 `svg` 和 `mg` 幕在按钮区显示一个只读标签“旧版 SVG / MG”，可以继续预览和导出，也可以切换成其他方式。

## 第 2 期：信息图动效、代码动效场景改成“按内容选版式”（核心）

### 2.1 问题

现在每种 `points.type` 只对应一种画面，DeepSeek 只能换动效名称，所以每条视频看起来都一样。需要一个**按信息关系组织的版式库**：DeepSeek 先判断这一幕的信息关系，再选版式并填结构化数据，代码负责排版和动画。

### 2.2 版式库（新增 `public/stage/info-forms.js`）

每个版式是一个注册项：

```js
{
  id: "dose-card",
  relation: "number",            // 信息关系
  label: "剂量卡",
  when: "一个关键剂量或数值，带条件说明",  // 发给 DeepSeek 的适用说明
  schema: {...},                  // 数据结构，前后端共用（同时写进 catalog.json）
  variants: ["solid", "outline", "split"],   // 视觉变体
  html(data, ctx) {},             // 生成 DOM
  animate(dom, data, t, ctx) {},  // 按时间驱动，必须是确定性的（逐帧截图）
  events(data, ctx) {},           // 音效事件，见 2.5
}
```

首批版式（每种信息关系 2–4 个，总数约 24 个）：

| 信息关系 relation | 版式 id | 画面 | 主要动效 |
|---|---|---|---|
| 开场/结论 `hook` | `big-answer` | 大字结论 + 一句解释 | 文字逐字落下、关键词高亮 |
| | `qa-flip` | 问题卡翻到答案卡 | 3D 翻转 |
| | `stat-hero` | 一个大数字 + 单位 + 说明 | 数字滚动计数 |
| | `art-answer` | 插画 + 结论（复用现有插画分屏） | 插画滑入 |
| 数值/剂量 `number` | `dose-card` | 剂量数值 + 条件 + 单位 | 计数 + 下划线描出 |
| | `weight-table` | 体重 → 剂量对照表，高亮当前行 | 行逐个出现、高亮条移动 |
| | `measure-scale` | 量杯或刻度尺，液面升到刻度 | 液面上升 |
| | `count-icons` | N 个图标表示次数（如每天最多 4 次） | 图标依次点亮 |
| 时间 `time` | `timeline-h` | 横向时间轴 | 进度线推进 |
| | `clock-24` | 24 小时钟面，标出服药时刻 | 指针转动、扇区填充 |
| | `interval-bar` | 两次服药间隔条（≥4 小时） | 间隔条伸展 |
| | `meal-band` | 饭前 / 饭中 / 饭后时间带 | 指示块滑到对应区间 |
| 步骤 `steps` | `flow-h` | 横向编号流程 | 连线描出、节点依次点亮 |
| | `steps-v` | 纵向步骤卡 | 逐卡上滑 |
| | `art-steps` | 插画 + 步骤分屏 | 插画缓推、步骤逐条出现 |
| | `cycle` | 环形循环（如“擦—晾—涂”） | 箭头环绕 |
| 对比 `compare` | `do-dont` | 左对右错，✓ 和 ✗ | 打勾、打叉 |
| | `table-compare` | 多属性对比表 | 列逐个展开 |
| | `before-after` | 前后对比 | 擦除分割线移动 |
| | `balance` | 天平或取舍 | 天平倾斜 |
| 警示/误区 `warning` | `myth-fact` | 误区卡被划掉，翻成正确做法 | 删除线 + 翻转 |
| | `alert-list` | 红黄分级警示列表 | 警示条闪入 |
| | `who-not` | 禁忌或慎用人群图标网格 | 图标逐个加禁止标记 |
| 清单 `checklist` | `check-list` | 勾选清单 | 逐条打勾 |
| | `icon-grid` | 图标网格（2×2 或 3×2） | 逐格弹出 |
| | `label-locate` | 药盒或说明书上定位栏目（复用 SVG 的 leaflet/carton 图形） | 放大镜移动、框选 |
| 原理 `mechanism` | `cause-chain` | A → B → C 因果链 | 箭头依次描出 |
| | `body-callout` | 身体或器官示意 + 引线标注（可配插画） | 引线描出、标注出现 |
| 收口 `summary` | `three-points` | 三要点收口 | 逐个出现后整体聚拢 |
| | `motto` | 口诀卡（一行押韵短句） | 逐字强调 |

做法要求：

- 用 SVG 或 CSS 实现，颜色全部用主题变量（`--v-primary` 等），保证在全部主题下都能看。图标统一用一套线性图标，放进 `public/stage/icons.js`，不要每个版式各画一套。
- 现有的插画分屏（`buildArtSceneHtml`）作为 `art-*` 版式的基础。其他版式也可以接一个可选的 `artUrl`：有插画就放在角落或背景位置，没有也要好看。
- 布局适配：读取 `LayoutEngine.mediaSize`。扁宽、窄、紧凑几种形态（`stage_video.layout_media_spec` 中的 `shape`）各给一套排版规则。版式的 `fits(size, data)` 返回 false 时，不能被选中。
- `card` 和 `scene` 两个 kind 都保留，共用这个版式库：
  - `card`：以文字为主，偏向 hook/number/checklist/summary，默认不配插画。
  - `scene`：以图形或插画为主，偏向 time/steps/compare/mechanism/warning，可以配插画。
  - 两者都带 `content.form`、`content.formData`、`content.variant`。

### 2.3 数据结构与校验

- `content` 新增字段：
  - `form`：版式 id
  - `variant`：视觉变体
  - `formData`：按版式 schema 填写的数据，例如 `dose-card` 是 `{value, unit, condition, note}`，`do-dont` 是 `{do:[...], dont:[...]}`
  - `motion` 可选
- 后端 `mix_plan.content_for` / `validate_production_plan` 和 `stage_video.validate_shot` 按 schema 校验，规则如下：
  - 字段类型和长度（标题不超过 10 字，说明不超过 16 字，可以按版式单独设置）。
  - **事实约束**：`formData` 里所有数字（阿拉伯数字或中文数字）和药名必须出现在本幕 `line` 或 `points` 里，否则这个方案作废。
  - 条目数量必须在版式允许的范围内（例如 `do-dont` 两侧各 1–3 条）。
- 校验失败时，用 `points` 自动推导一个默认版式（沿用现有的 `pointVisuals` 映射），保证一定能出画面。
- 旧数据兼容：只有 `visual` 或 `motionStyle` 的旧 content，映射到等价的新版式（例如 `visual: compare` → `do-dont`），旧作品不会变样。

### 2.4 让每次生成都有不同表现

1. **Mix 编排**（`mix_plan.arrange`）：给 DeepSeek 一份 `formCatalog`，包含 `id`、`relation`、`when`、`schema` 和当前布局下的可用性。指令要求：
   - 先判断本幕信息关系，再选最贴合的版式。
   - 同一条视频里**相邻两幕不用同一个版式**；5 幕以上至少用 4 个不同版式。后端也要检查这一点，违反时把后一幕换成同一 relation 下的另一个版式。
   - `variant` 由后端按 `hash(workId + 幕序号 + 重做次数)` 轮换，不交给模型。
2. **本幕重新制作**（`produce_shot`）：新方案必须换 `form`，或至少换 `variant` 加 `motion`。`production_structure` 改为比较 `(form, variant, motion)`。
3. **工作台**：分镜编辑器在“信息图动效 / 代码动效场景”下面加一个“版式”下拉，按信息关系分组、显示中文名，可以手动切换；切换后用现有 `points` 自动填入 `formData`。再加一个“换个版式”按钮，只在同一 relation 内轮换，不调用模型、不产生费用。

### 2.5 动效与音效

- 每个版式的 `events()` 输出语义事件，事件类型扩展为：`count`（数字滚动结束）、`check`、`cross`、`flip`、`draw`（连线描完）、`warning`、`item-focus`。
- `catalog.json` 的音效包（`sfx-pack`）补上这些事件的映射，没有对应声音的事件跳过。`player.collectEvents` 现有的去重规则（同一幕最多 4 个、间隔 ≥0.35 秒）继续保留。
- 动效时长跟口播节拍走：用 `cues` 的 `focus` 决定第几条要点什么时候出现（沿用 `resolveActiveFocus`），不能所有要点一开场就一起出来。

### 2.6 验收

- 新增 `tests/stage-forms.mjs`：每个版式在 2 套主题 × 3 种布局形态下截图；检查文字不溢出（元素没有超出 media slot）、没有空白画面，并输出一张总览拼图供人工看。
- Python：校验器单测，覆盖 schema 错误、数字不在口播里、相邻重复、旧 content 映射。
- 用假 DeepSeek 生成同一脚本 3 次，三次的版式序列不能完全相同。
- 用真实 DeepSeek 跑 2 个选题（例如“儿童退烧药怎么量”和“抗生素能不能自己停”），导出 MP4，人工检查。

## 第 3 期：素材库素材 → 贴纸（叠加，不替换）

### 3.1 目标

贴纸是叠加在任意一幕（image/card/scene/clip）上面的小图层：在合适的时机出现、放在合适的位置、配合适的音效，**不替换内容**。

### 3.2 数据结构

每一幕新增 `stickers` 数组，每幕最多 2 个，全片建议不超过 8 个：

```json
{
  "assetId": "builtin:image/fluent-warning",
  "cue": 1,                 // 在第几句字幕出现（按 cues 下标）
  "keyword": "千万别",       // 可选：必须出现在该 cue 文本里，用于精确对时
  "anchor": "media-tr",     // 位置锚点，见下
  "size": "m",              // s / m / l，对应内容区短边的 14% / 20% / 26%
  "enter": "pop",           // pop / bounce / slide / stamp / float
  "hold": "stay",           // stay（留到本幕结束）/ cue（只在该句期间显示）
  "sfx": "auto"             // auto / none / 素材库 sfx id
}
```

- 锚点由 `LayoutEngine` 计算，只允许预设位置：
  - 内容区四角：`media-tl`、`media-tr`、`media-bl`、`media-br`
  - `headline-end`：标题末尾
  - `item-N`：第 N 条要点旁，代码版式会给每条要点加 `data-anchor`
- 渲染时检测是否遮挡文字（和 `.pt-focus-target`、标题、字幕的矩形相交）。遮挡就依次换到其他角，全都遮挡就缩小一档。
- 出现时间 = 该 cue 的 `start`；有 `keyword` 时，按关键词在句子里的字符位置比例往后推。

### 3.3 渲染与音效

- 新增 `public/stage/stickers.js`，在 `player.drawFrame` 渲染完内容之后，在 media slot 上叠加一个 `.stage-sticker-layer`。动画必须是确定性的，只由 `time` 决定。
- 音效：每个贴纸出现时产生事件 `{type:"sticker", sfxId}`。
  - `server.stage_sound_mix` 遇到带 `sfxId` 的事件，直接用素材库里的那个音效，不走音效包映射。
  - `auto` 按贴纸标签映射：警示 → warning 类，勾选或正确 → check，其他 → pop。
  - 全片设置里加一个开关“贴纸音效”（默认开），与“画面事件音效”分开。
- `frameSignature`：贴纸入场动画期间返回 null，保证逐帧截图正确。

### 3.4 自动加贴纸（模型）

- 新增后端函数 `mix_plan.plan_stickers(client, model, item, script, library)`：
  - 输入：全片脚本，加上每幕的候选贴纸（用现有 `asset_candidates` 按标签匹配，只取 `kind=image` 且带“贴纸”标签的素材）。
  - DeepSeek 返回每幕 0–2 个贴纸，包括 `assetId`、`cue`、`keyword`、`anchor`、`size`、`enter`、`sfx`，以及 `reason`。
  - 规则：只在关键提醒、正确或错误判断、数字或时间点、情绪转折处加；开场幕和结尾幕可以各加 1 个；不要每幕都加；同一贴纸全片最多用 2 次。
  - 后端校验：`assetId` 必须在候选里，`cue` 下标合法，`keyword` 必须在该句里，`anchor` 必须在允许列表里。
- 调用时机：Mix 编排完成后自动跑一次（只用 DeepSeek，费用很低），设置里可以关闭；单幕可以点“重新配贴纸”。

### 3.5 工作台 UI

- 分镜编辑器新增“贴纸”区块：列出本幕贴纸，每个可以改出现的句子（下拉显示字幕文本）、位置（锚点按钮）、大小、入场方式和音效（自动 / 无 / 选择），也可以删除；还有“从素材库添加贴纸”。
- 工具栏加“自动加贴纸”（全片）。
- 预览播放器能实时看到贴纸和听到音效（沿用现有音效预览）。

### 3.6 素材

- 现在素材库只有 4 张 Fluent 贴纸。按现有 `stickers/fluent/` 的做法（MIT 许可，在 `素材来源与授权.md` 登记），补到 30–40 个用药科普常用贴纸：药片、胶囊、注射器、体温计、听诊器、水杯、闹钟、日历、对勾、叉号、警示、禁止、灯泡、点赞、放大镜、婴儿、老人、孕妇、冰箱、太阳、月亮、床、饭碗、心形、眼睛、鼻子、牙齿、病毒、盾牌等。每个都要写 `tags`，并带上“贴纸”标签。
- 用户上传的带透明背景的 PNG，也可以加“贴纸”标签后使用。

### 3.7 迁移

- `stage-studio.js` 的 `normalizeWork`：旧的 `asset` 幕转为 `card`（默认版式），原素材作为一张 `media-br`、`size: l` 的贴纸。`stage_video.validate_shot` 的 asset 分支保留，用于兼容未迁移的数据。
- 移除 `asset` 的“制作方式”按钮，以及 Mix 中的 asset presenter。

### 3.8 验收

- 渲染测试：贴纸在各个锚点不遮挡文字；入场动画逐帧正确；导出的 MP4 在贴纸出现时刻有对应音效（复用 `tests/compare-stage-sound.py` 的思路，检测音频峰值时间）。
- Python：`plan_stickers` 校验单测，覆盖非法 id、cue 越界、keyword 不在句内、数量超限。
- 旧作品中的 asset 幕迁移后能导出。

## 第 4 期：AI 演示视频 / AI MG 动画（视频模型生成，只在分镜编辑里用）

### 4.1 设计

- 新 kind：`clip`。用 `content.clipStyle` 区分两个按钮：
  - `demo`（AI 演示视频）：写实或半写实，演示实际操作，例如滴眼药、量取混悬液、看说明书。
  - `mg`（AI MG 动画）：扁平 2D 动态图形风格，表现原理或过程，例如药物在体内吸收、退烧过程。
- 只在**分镜编辑器**中出现。Mix 不会自动选它，因为费用高。Mix 可以给出 `clipSuggestion`（不超过 160 字），编辑器显示“建议用 AI 视频”。
- 生成流程（全部按需，每一步前先确认费用）：
  1. DeepSeek 根据本幕口播和要点写 `clipPrompt`。用户可以编辑：主体、动作顺序、镜头和风格；禁止出现文字、品牌和医生形象。
  2. 生成首帧：用 Seedream 按内容区比例出一张图，复用插画生成的流程（`prepareArt` / `installImages`），风格前缀按 `clipStyle` 区分。用户也可以从素材库选首帧。
  3. 调 Seedance：复用 `server.source_clip`（首帧 `first_frame`，`generate_audio: False`）。时长 = 本幕估算秒数向上取整，限制在 4 到 `VIDEO_MODELS[model][2]` 之间。分辨率默认 720p。
  4. 结果存进 `/media`，写入 `content.clip = "/media/xxx.mp4"`、`content.clipPoster`，以及模型、秒数、实际费用。可以“收入素材库”（新增素材 kind `video`，需要扩展 `asset_library`）。
- 费用确认弹窗：调用 `work_costs.video_cost` 估算（按分辨率 × 秒数），加上首帧的 `image_cost`。显示“预计 ¥x.xx，按方舟实际用量结算”，用户确认后才提交。生成失败或排队中时，沿用 `source_clip` 的防重复计费逻辑（`submitting` 状态）。

### 4.2 渲染

- 预览：`Contents.clip` 用 `<video muted>`，`draw` 时设置 `currentTime = localTime`。
- 导出：逐帧截图时不能依赖 `<video>` 寻帧。`render_stage_video` 在渲染前，用 FFmpeg 把每个 clip 按 `fps` 和内容区尺寸抽帧成 JPEG 序列，再把序列目录和帧数写进 manifest。`Contents.clip` 在导出模式下按 `floor(localTime*fps)` 显示对应帧的 `<img>`。
- 时长对不上时：clip 比本幕短，停在最后一帧（可选慢放到 0.85×）；比本幕长就截断。
- 内容区上方仍可以叠加标题和要点（`overlay: points / title / off`，沿用 MG 现有选项），也可以叠贴纸。
- `frameSignature` 对 clip 幕返回 null。

### 4.3 后端

- `asset_library.LAYOUT_CONTENTS` 加 `clip`，内置布局的 `supports` 全部加上 `clip`。
- `stage_video.validate_shot` 新增 clip 分支：校验文件存在、是 mp4、`clipStyle` 合法、`overlay` 合法。
- 新增作业类型：例如 `stageClip`，复用 images 和 video 作业的排队、进度、失败重试和费用记录（`record`）。
- `catalog.json` 的 presenters 增加 `clip`，标注 `cost: "方舟按视频 Token 收费"`，但不放进 Mix 的 presenters。

### 4.4 旧 svg / mg 幕

保留渲染器，旧作品可以继续导出。编辑器按钮区显示“旧版 SVG / MG”，提供“改用 AI 视频”按钮：把口播和 `mgRequest` 带进 `clipPrompt`。

### 4.5 验收

- 假接口测试：用一个本地 mp4 模拟 Seedance 返回。端到端覆盖：选 AI 演示视频 → 编辑描述 → 弹出费用确认 → 生成 → 预览 → 导出 MP4。检查时长、clip 帧与时间对齐（抽 3 帧比对）、叠加文字可见。
- 取消费用确认时不提交任何付费任务。
- 真实环境只用 Seedance 2.5 Flash 480p 跑 1 次，确认费用记录和实际一致。
